# ByeByeVPN: основная сводка и вывод

## Источник и область проверки

Сводка контрольного сканирования одного сервера инструментом [ByeByeVPN](https://github.com/pwnnex/ByeByeVPN). В таблице приведены наблюдения этого запуска; они не означают гарантированную неуязвимость к обнаружению или блокировкам.

Точная версия и хеш сканера, а также дата запуска в сохранённом выводе не указаны.

## Основные результаты

| Проверка | В предоставленном выводе |
|---|---|
| Итоговый балл | **100/100 — CLEAN** |
| Определённый стек | Обычный TLS/HTTPS origin; прямой сигнатуры VPN не найдено |
| Сильные / слабые сигналы | **0 / 0** |
| Эмуляция ТСПУ | **PASS / ALLOW**, попадания A=0, B=0 |
| HTTPS | TLS 1.3, ALPN h2; сертификат доверенного центра в оценке инструмента |
| HTTP поверх TLS | Получен корректный HTTP-ответ 404, заголовок Server: nginx |
| Реакция на восемь нестандартных проб | Семь без ответа, одна с TLS alert; в матрице J3 — MEDIUM |
| UDP-пробы | На проверенные WireGuard/AmneziaWG/Hysteria2/QUIC пробы ответов не получено |
| GeoIP | Источники расходятся; один провайдер отметил hosting |
| CT-журнал | Запрос к crt.sh завершился ошибкой; отсутствие записи не установлено |

## Предупреждение внутри самого отчёта

TCP-сканирование сообщило о **105 открытых портах с близким RTT**. Одновременно инструмент предупредил, что это похоже на вмешательство WARP, локального прокси или промежуточного сетевого устройства, принимающего соединения. Наличие такого устройства не доказано, но достоверность списка портов самим сканером поставлена под сомнение.

Поэтому строку итоговой матрицы о «разнообразном сервере со 105 портами» нельзя использовать как подтверждённый плюс конфигурации. Итоговые 100/100 приводятся буквально как результат инструмента, с этим ограничением. Устанавливать причину предупреждения и фактическое число доступных портов нужно отдельной проверкой из известной сетевой среды.

## Что означает результат простыми словами

В этом запуске доступный HTTPS-вход выглядел для сканера как обычный веб-сервер. Проверки не дали ему достаточных признаков для уверенного определения VPN. Это полезное наблюдение для схемы, в которой на протокольных доменах обслуживается обычная веб-страница.

Результат **не доказывает**, что VPN невозможно обнаружить или заблокировать. PASS / ALLOW — решение модели, встроенной в утилиту, а не полученное от реального оборудования оператора разрешение. Не проверены все домены, транспорты, клиенты, длительные потоки и точки наблюдения.

Отсутствие ответа UDP не доказывает отсутствие протокола или его неработоспособность: возможны фильтрация и отбрасывание неаутентифицированных запросов. HTTP 404 подтверждает наличие HTTP-ответа для конкретной пробы, но не проверяет правильность сайта на каждом настроенном имени. Одинаковый сертификат при разных SNI также не исключает другие маршруты, не попавшие в пробу.

## Вывод для x-tuna

Предоставленный запуск показывает благоприятный результат внешней эвристической проверки HTTPS-входа: **CLEAN 100/100**, без прямых VPN-сигнатур по классификатору ByeByeVPN. Из-за предупреждения о TCP-сканировании и ограниченного охвата его следует использовать как дополнительное наблюдение вместе с браузерной и клиентской проверкой, а не как гарантию устойчивости к DPI.

Разработчик инструмента рекомендует запускать внешнюю проверку без VPN/прокси и средств модификации трафика на компьютере наблюдателя. См. [условия запуска в исходном репозитории](https://github.com/pwnnex/ByeByeVPN#prerequisites-read-before-scanning). Скрипт ByeByeVPN в x-tuna не встроен и не распространяется как его компонент. Рекомендации сканера по изменению SSH или сети не применялись автоматически.
