# Решение проблем

Сначала запишите пункт меню и точное сообщение. Повторное применение без понимания причины может скрыть исходную ошибку. Адреса и идентификаторы в публичном отчёте заменяйте примерами.

| Симптом | Что проверить | Следующий шаг |
|---|---|---|
| `x-tuna: command not found` | Завершилась ли установка команд | Запустить проверенный shell с `--install-tui`, затем заново открыть меню |
| Не совпал SHA-256 | Оба ли файла из одной поставки | Скачать согласованную пару; не менять checksum вручную |
| Не найдена база LucX | Установлена ли панель, соответствует ли путь | `--audit`, при необходимости read-only `--db`; не создавать пустую БД вместо рабочей |
| В плане нет ожидаемого профиля | Включён ли inbound/Host в панели | Сверить LucX, выполнить свежий аудит |
| Сайт не открывается | DNS, публичный порт, SNI и сертификат | Проверить конкретное имя, покрытие заглушками и `--validate` |
| Сайт работает, VPN нет | Транспорт, путь/serviceName, TLS/Reality, подписка | Обновить профиль в клиенте и проверить один маршрут отдельно |
| VPN работает, сайт нет | Предусмотрен ли веб-маршрут для этого имени | Проверить отчёт покрытия, не менять Naive Caddyfile вручную |
| Браузер ругается на сертификат | SAN/срок/цепочка, имя запроса | Раздел сертификатов и `--certificate-check` |
| Подписка пустая/не импортируется | Путь, порт, доступность sidecar, формат клиента | Проверить выдачу и клиентскую совместимость без публикации URI |
| Optional TrustTunnel backend не найден | Какой backend реально использует LucX | Посмотреть статус LucX отдельно; отсутствие кандидата не равно отказу VPN |
| Применение заблокировано staging | Полный текст причины и режим приёмки | Сопоставить поддержанный профиль/компонент; не использовать force как обход |
| После Cloudflare restriction пропал доступ | Проксируемость записи и нужный порт | Проверить через CDN, при необходимости согласованно отключить ограничение |
| После обновления маршруты устарели | Статус задания обновления и drift | `--repair-check`, затем подтверждённый `--repair-apply` |
| Занята блокировка | PID/операция из сообщения | Дождаться окончания; не удалять lock у работающего процесса |
| Naive: устарел источник после запуска LucX | Завершился ли запуск панели и внутреннего моста | Пункт 6 главного меню: повторная проверка и новый план; исходный Caddyfile не редактировать |
| Naive: защищённые настройки не подтверждены | Совпадают ли клиенты, внутренний listener и настройки с сохранённой конфигурацией | Исправить указанное расхождение; повторная проверка не отключает защиту |
| Hook ACME зарегистрирован, расписание не проверено | Права root crontab, формат задания и состояние cron | Меню проверяет Debian cron автоматически; обёртки и другие планировщики могут требовать отдельной диагностики. Регистрация hook не доказывает будущее продление |
| Расписание найдено, cron неактивен | Состояние `cron.service` | Существующее задание не выполняется неактивной службой; после восстановления службы откройте меню заново |
| UDP в автотесте зелёный, клиент не работает | Устанавливает ли клиент реальный туннель | Зелёная отправка UDP не подтверждает ответ/аутентификацию |
| Скорость не выросла после BBR | Ядро, статус sysctl, нагрузка и канал | Сравнить измерения; при необходимости удалить настройку и проверить фактические sysctl |

## Полезные команды

```bash
x-tuna --audit
x-tuna --validate
x-tuna --repair-check
x-tuna --certificate-check
x-tuna --network-tuning-status
```

Не отправляйте сырые БД, приватные ключи, токены DNS, Caddyfile с credentials или полную ссылку подписки. Для публичного issue достаточно версии, обезличенного сообщения, последовательности действий и результата одного конкретного профиля.

## Откат

Откройте **4 → 3** и изучите доступный backup и затрагиваемые объекты. Обычный откат проверяет конфликты. Принудительный откат допускает перезапись изменённых управляемых файлов, поэтому требует отдельного осознанного решения. Резерв x-tuna не заменяет снимок VPS.
