# Конфигурация и manifest

## Назначение

Manifest является декларативным описанием обнаруженной топологии и выбранных
операций. Он не является копией базы LucX и не должен содержать клиентские
секреты. Текущая поддерживаемая версия схемы: `v3`.

## Основные разделы

| Раздел | Содержание | Изменяется обычным apply |
|---|---|---:|
| `os` | ОС, архитектура, ресурсы | нет |
| `lucx` | версия, пути, панель, подписка | только разрешённые public metadata |
| `protocols` | обнаруженные inbound’ы и transport | нет |
| `network` | TCP/UDP/SNI topology | через generated обвязку |
| `decoys` | сайты и способы доставки | да |
| `sidecar` | состояние и согласие sidecar | да |
| `certificates` | пути и метаданные сертификатов | только после отдельного согласия |
| `cloudflare` | orange-cloud ACL | да |
| `firewall` | режим и защищаемые порты | да |
| `dns` | системные резолверы | да |
| `integrity` | hash-only snapshots | автоматически |
| `backup` | каталог и состав backup | автоматически |
| `updates` | worker и источники обновлений | отдельно |

## Поля LucX

Обычная транзакция может менять только явно перечисленные поля:

- `settings.webDomain`;
- `settings.subDomain`;
- `settings.webBasePath`;
- `settings.subURI`, `settings.subJsonURI`, `settings.subClashURI` при включённой
  синхронизации clean URL;
- `share_addr` выбранного публичного inbound’а;
- включённые Host endpoints этого inbound’а;
- пути сертификатов панели и подписки после второго подтверждения.

Не изменяются клиенты, inbounds, outbounds, transport, credentials, UUID,
`subId`, внутренние порты и содержимое сертификатов.

## Порты

- `internal_port` — обнаруженный listener LucX; не переписывается для создания
  внешнего endpoint.
- `public_port` — внешний порт публикации.
- `udp_public_port` — отдельный UDP endpoint для смешанного TCP/UDP inbound.
- TCP/443 может принадлежать HAProxy, а UDP/443 одновременно может принадлежать
  Hysteria2; это разные пространства сокетов.
- При прямой публикации без NAT public port обязан совпадать с реальным listener.

## SNI и transport

SNI читается заново при каждом audit/repair. Для Reality учитываются все
`realitySettings.serverNames`; значения не зашиваются в код. XHTTP разрешается
для dedicated non-root path. Если path равен `/`, безопасное разделение с
браузерным корнем невозможно и применение блокируется.

## Миграции

`decoys.zone_apex` хранит явно выбранный корень DNS-зоны, например `example.test`.
Он проверяется как доменное имя. Старый manifest без поля поддерживается: мастер
предлагает суффикс домена панели, но позволяет исправить его до построения плана.
При миграции зоны записывается выбранная новая зона целиком.

Сохранённые `decoys.extended_routes` должны соответствовать текущим inbound:
пропуски, дубликаты, изменённые endpoint/transport или неподтверждённая стратегия
блокируют генерацию и требуют нового плана. RAW/TCP Xray не мигрируется автоматически.

Миграция старой схемы должна быть чистой функцией: она преобразует структуру в
памяти и не обращается к серверу. Неизвестная более новая схема только читается
и блокирует изменение до обновления конфигуратора.

Тесты миграций находятся в `tests/test_migrations.py`.
