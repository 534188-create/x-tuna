# Команды CLI

Основная команда — `x-tuna`, совместимая — `lucx-post-configure`. Без параметров открывается меню. `--help` показывает справку именно установленной версии. Команды изменения требуют административного доступа.

| Параметр | Назначение |
|---|---|
| `--tui` | интерактивное текстовое меню (по умолчанию) |
| `--audit` | аудит сервера без изменений |
| `--plan` | интерактивное построение плана без изменений |
| `--apply` | применить утверждённый manifest |
| `--validate` | проверить последнюю применённую конфигурацию |
| `--resume` | повторить manifest последнего неудачного запуска |
| `--rollback` | восстановить файлы из последнего backup |
| `--reconfigure` | изменить управляемые домены и найти подходящий wildcard-сертификат |
| `--repair-check` | проверка восстановления после обновления без изменений |
| `--repair-apply` | транзакционно пересобрать маршруты по текущим данным LucX |
| `--install-tui` | установить постоянные команды TUI и lucx-sub-repair |
| `--certificate-check` | найти сертификат, покрывающий управляемые домены |
| `--update-lucx` | запустить официальный updater LucX и post-update repair |
| `--configure-decoys` | создать или синхронизировать заглушки всех протокольных доменов |
| `--trusttunnel-backend-probe` | проверить переданный TrustTunnel backend без изменений |
| `--protocol-test` | комплексный автотест всех протоколов и сайтов-заглушек (live probe) |
| `--network-tuning-status` | показать статус TCP BBR, очередей FQ и буферов |
| `--network-tuning-apply` | применить оптимизацию TCP BBR и сетевых буферов |
| `--network-tuning-revert` | удалить файл настройки BBR и перечитать оставшиеся sysctl-конфиги (не гарантирует возврат прежних значений) |
| `--dns-diagnostic` | расширенная диагностика DNS и изоляции портов |
| `--manifest` | путь входного или выходного manifest |
| `--output` | записать JSON-результат в этот файл |
| `--db` | переопределить путь к базе LucX только для чтения |
| `--yes` | подтвердить итоговое применение или откат |
| `--force` | разрешить откат поверх изменённых managed-файлов |
| `--update-source` | источник архива обновления LucX |
| `--mirror-url` | пользовательский HTTPS tar-архив обновления LucX |
| `--backend-path` | путь к локальному TrustTunnel backend для read-only проверки |
| `--backend-port` | loopback-порт для read-only проверки TrustTunnel backend |
| `--github-proxy` | шаблон HTTPS GitHub proxy с {url}; можно указать несколько раз |
| `--decoy-routing-mode` | внутренний селектор совместимости; TUI использует автоматический режим |

## Примеры

```bash
x-tuna --audit
x-tuna --certificate-check
x-tuna --validate
x-tuna --repair-check
x-tuna --network-tuning-status
x-tuna --help
```

Для подготовки манифеста: `x-tuna --plan --manifest /root/x-tuna-plan.json`. Для применения сохранённого плана: `x-tuna --apply --manifest /root/x-tuna-plan.json`. Манифест приватный; не прикладывайте его целиком к публичному issue.

`--protocol-test` и `--dns-diagnostic` выполняют активные сетевые обращения. Это диагностика, но не пассивное чтение файлов. Ограничения — в [тестировании](TESTING_RU.md).

`--yes` пропускает соответствующее финальное подтверждение, поэтому в инструкции для новичка он не используется. `--force` относится к конфликтам отката; не применяйте его как средство принудительно включить неподдержанный маршрут.

`--update-worker` и `--update-job-id` — внутренние параметры фонового обновления; вручную их задавать не нужно.

## Исключение: сетевые настройки

`--network-tuning-apply` и `--network-tuning-revert` изменяют систему сразу, без цифрового подтверждения. `--yes` для них не требуется. Revert удаляет файл BBR и перечитывает sysctl; не гарантирует прежние или стандартные значения параметров. Для ознакомления используйте только `--network-tuning-status`, для диалога — меню 3 → 2.
