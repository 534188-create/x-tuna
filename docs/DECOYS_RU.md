# Сайты-заглушки

## Назначение

Заглушка обслуживает обычный браузерный HTTPS-запрос, но не должна перехватывать
VPN handshake. Создание HTML и его внешняя публикация являются разными этапами.

## Файлы

Стандартный корень сайта:

```text
/var/www/lucx-decoys/<домен>/index.html
```

Каталоги, читаемые Nginx, должны иметь подходящие режимы доступа. Существующий
пользовательский каталог не перезаписывается без отдельного подтверждения.

## Классификация

| Статус | Файлы создаются | Внешняя публикация |
|---|---:|---|
| `direct_tcp_decoy` | да | Nginx через HAProxy |
| `udp_with_tcp_decoy` | да | TCP-сайт, UDP остаётся VPN |
| `reality_endpoint_decoy` | да | endpoint, camouflage SNI не трогается |
| `existing_fallback_observed` | возможно | владелец fallback не меняется |
| `naive_caddy_owned_readonly` | нет в Caddyfile | определяется LucX/Caddy |
| `blocked_sni_collision` | локально возможно | маршрут запрещён ради VPN |
| `unsupported_safe` | по плану | маршрут запрещён |

## SNI collision

Если браузер и VPN используют одинаковые SNI, а надёжного протокольного признака
нет, VPN получает приоритет. Нельзя угадывать тип трафика по User-Agent, порядку
пакетов или случайным байтам ClientHello.

## Проверка

Managed site проверяется TLS handshake, HTTP GET/HEAD, ожидаемым marker-заголовком,
ответом с внешнего интерфейса и подтверждением, что ответ не принадлежит VPN
backend. HTTP 200 без marker не считается успешной проверкой. Дубликат marker,
совпадение подстроки или marker в теле также отклоняются.

Публичный TLS проверяет CA и hostname. GET/HEAD должны пройти через HTTP/1.1 и
реальный HTTP/2; для h2 нужен системный curl с HTTP2. Его отсутствие даёт
`not_tested` и запрещает успешную managed health-проверку. В расширенном режиме
также проверяются внутренние TLS и h2c targets. Все blocked/skipped сайты остаются
в матрице и не позволяют объявить полную браузерную приёмку.

Успешные browser probes не подтверждают VPN-соединения. Без функционального
VPN observer результат остаётся `not_tested`, общая приёмка — `partial`.

## Корневой домен

При миграции зоны может создаваться заглушка для apex, например `example.test`.
Это не означает автоматическую безопасность всех поддоменов: каждый домен проходит
классификатор.

Мастер записывает корень в `decoys.zone_apex`. Для домена панели
`panel.admin.example.test` можно явно выбрать `example.test`; нельзя считать
`admin.example.test` корнем зоны без проверки. В матрицу включаются все сайты,
даже если у них нет отдельного inbound. Чужой Reality SNI также блокирует сайт.

## HTTP transport

В расширенном режиме WS/HTTPUpgrade разделяются по точному пути, GET и
Connection/Upgrade, gRPC — по POST, Content-Type и точным RPC путям сервиса.
XHTTP сохраняет отдельный путь и его потомков; регистр пути имеет значение.
Host HTTP-запроса и SNI повторного TLS-соединения берутся из обнаруженной
конфигурации и могут различаться.

Xray RAW/TCP не оборачивается автоматически. Существующий listener сохраняется,
а сайт получает явный запрет до отдельно согласованной миграции транспорта.
Нативный AnyTLS имеет отдельную стратегию. Неизвестный transport и неполный
кеш маршрутов не должны превращать занятый VPN-домен в свободный сайт.
