# Полная карта функциональности

Здесь перечислены возможности x-tuna, способы их запуска и условия работы. Результат настройки зависит от конфигурации LucX и установленных на сервере компонентов.

| Область | Возможности | Где открыть | Условия и границы |
|---|---|---|---|
| Аудит | ОС, LucX, inbound, порты, сертификаты и состояние | Статус; `--audit` | Читает обнаруженное состояние, не создаёт VPN |
| План | Интерактивный сбор и вывод манифеста | Первичная настройка; `--plan` | План не равен применению; сохранённый файл содержит приватные настройки |
| Применение | Внешние конфиги, проверки, backup, health и откат | Первичная настройка; `--apply` | Зависит от совместимости схемы, компонентов и маршрутов |
| Повтор | Повторить последний неудачный манифест | `--resume` | Не универсальный crash recovery |
| Домены | Управляемые домены, миграция DNS-зоны, сертификат | Настройка → Домены; `--reconfigure` | DNS и покрытие сертификата должны быть согласованы |
| HTTPS-вход | HAProxy/Nginx, публичные адреса панели/подписки/протоколов | План маршрутизации | Внутренние listener-порты сохраняются |
| Заглушки | Синхронизация сайтов, статус покрытия, расширенная маршрутизация | Настройка → Заглушки; `--configure-decoys` | Неизвестный трафик не угадывается; полный набор вариантов не подтверждается одним сайтом |
| Подписки | Необязательный sidecar, совместимые форматы, фильтрация | Настройка → Подписки | qWDTT исключён, TrustTunnel HTTPS/h2; совместимость клиента проверяется отдельно |
| Сертификаты | Поиск пары, проверка покрытия, выпуск DNS-01, продление | Настройка → Сертификаты; `--certificate-check` | Нужны права DNS/API и корректные renewal-настройки |
| TrustTunnel | Статус LucX, проверка и выбор отдельного backend | Настройка → TrustTunnel; `--trusttunnel-backend-probe` | Отсутствие optional backend не доказывает отказ работающей службы LucX |
| DNS | Выбор системных резолверов, измерение задержки, диагностика | Сеть → DNS; `--dns-diagnostic` | Результат зависит от сети и доступности резолверов |
| Firewall/CDN | nftables, ограничение Cloudflare origin панели и подписки | Сеть → Cloudflare | Не применяется как универсальный CDN для всех VPN |
| BBR | Статус BBR/FQ/буферов, применение, удаление настройки | Сеть → Оптимизация; `--network-tuning-*` | Требуется поддержка ядра; оставшиеся sysctl-конфиги определяют результат |
| Автотест | Веб-пробы, Naive/AnyTLS-пробы, sidecar, UDP | Статус; `--protocol-test` | Есть фиксированные предположения о доменах и портах; не полный клиентский тест |
| Валидация | Проверка установленной управляемой конфигурации | Статус; `--validate` | Не доказывает обход DPI |
| Ремонт | Проверка drift и пересборка обвязки из текущих данных | Обслуживание → Ремонт; `--repair-check/--repair-apply` | Новый или несовместимый inbound может потребовать нового плана |
| Обновление LucX | Источники auto/SourceCraft/GitHub/custom, worker и post-update repair | Обслуживание → Обновление; `--update-lucx` | Обновляется панель; это не автообновление публикации x-tuna |
| Backup/rollback | Просмотр резервов, штатный и принудительный откат | Обслуживание → Бэкапы; `--rollback` | Принудительный режим предназначен для разбора конфликтов |
| Постоянные команды | Установка `x-tuna`, `lucx-post-configure`, `lucx-sub-repair` | Обслуживание → Команды; `--install-tui` | Выполняется отдельно от первичного apply |
| Перезагрузка | Явная команда после двух подтверждений | Обслуживание → Перезагрузка | Прерывает подключения, не выполняется автоматически |

## Протоколы и транспорты

Discovery и планировщик работают с обнаруженными inbound LucX, включая Xray-профили, Naive, TrustTunnel, AnyTLS, Mieru, AmneziaWG и Hysteria. Для Xray встречаются VLESS, VMess и Trojan с транспортами WS, HTTPUpgrade, gRPC, XHTTP и вариантами TLS/Reality. Фактическое покрытие конкретного сочетания отражают план и отчёт; перечисление не обещает одинаковую поддержку всех вариантов во всех режимах приёмки.

Веб-сайт обслуживается по HTTP/HTTPS. У UDP-протокола может быть сайт на том же имени, но это отдельный TCP-маршрут. qWDTT не включается в клиентскую подписку. TrustTunnel QUIC/HTTP3 не публикуется как поддержанный клиентский профиль.

## Строгая функциональная приёмка

В исходнике остаётся отдельный режим `require_full_acceptance`: его staging имеет собственную ограниченную область поддержанных профилей и компонентов. Если он включён и обнаружен неподдержанный элемент, блокировка не означает отсутствия всего протокола в LucX. Не включайте/отключайте этот параметр для обхода ошибки без понимания плана.
