# Проверки и границы результатов

## Три разных вида проверки

1. Локальные тесты проверяют код на подготовленных сценариях.
2. Серверная диагностика проверяет доступность и сохранённую конфигурацию в текущей среде.
3. Клиентская приёмка проверяет реальную работу вашего профиля в пользовательском приложении.

Успех одного вида не заменяет остальные. Внешняя эвристика ByeByeVPN — отдельное наблюдение, описанное в [сводке](BYEBYEVPN_RU.md).

## Встроенный автотест

`x-tuna --protocol-test` и соответствующий пункт раздела «Статус и диагностика» выполняют активные пробы. Текущий `protocol_test.py` использует манифест, но также имеет фиксированные предположения: HTTPS/443, sidecar loopback/21000, добавление test1…test8, отдельные UDP-порты и выбор имён Naive/AnyTLS. Домен по умолчанию — example.test; для проверки укажите свой домен.

Эта команда не является универсальным тестом произвольной топологии. Для нестандартных имён и портов сначала сопоставьте фактические цели с вашим манифестом. Не запускайте её без проверки целей как доказательство всей матрицы.

Особенности интерпретации:

- UDP-проба отправляет датаграмму и не ожидает подтверждённого VPN-обмена. Успех означает успешный `sendto`, а не аутентификацию или ответ backend.
- В части TLS-проб проверка сертификата отключена по умолчанию. Их зелёный статус не подтверждает доверенную цепочку и совпадение имени.
- Проверка HTTP-ответа панели или health sidecar не доказывает корректность всех персональных подписок.
- Протокольные пробы без ваших действующих credentials не заменяют подключение пользовательского клиента.

Учитывайте эти ограничения при оценке результатов диагностики.

## Ручная приёмка

1. Зафиксировать версию и SHA-256 установленного shell.
2. Проверить корневой домен и каждый настроенный домен в браузере: ожидаемый сайт, правильный сертификат.
3. Проверить доступ к панели по её пути и внешнему порту.
4. Обновить подписку в Throne либо другом совместимом клиенте. Для неподдерживаемого клиентом протокола использовать подходящее приложение.
5. Подключить каждый профиль отдельно: загрузка страницы, двусторонняя передача, параллельные запросы, отключение и повторное подключение.
6. Проверить qWDTT-фильтрацию и TrustTunnel HTTPS/h2.
7. Проверить повторное применение и штатный откат на тестовом сервере с резервной копией.
8. Записать результаты «успешно / ошибка / не проверено» по каждому протоколу и транспорту без секретов.

## Полный локальный gate

В Windows, из корня репозитория, с Python 3.11+:

```powershell
$env:PYTHONPATH = 'src;tests'
python -m compileall -q src tests tools
python -m unittest discover -s tests
python tools/check_documentation.py .
python tools/scan_secrets.py .
python tools/build_installer.py
$first = (Get-FileHash dist/lucx-post-configure.sh -Algorithm SHA256).Hash
python tools/build_installer.py
$second = (Get-FileHash dist/lucx-post-configure.sh -Algorithm SHA256).Hash
if ($first -ne $second) { throw 'Сборки различаются' }
& 'C:\Program Files\Git\usr\bin\sh.exe' -n install.sh
& 'C:\Program Files\Git\usr\bin\sh.exe' -n dist/lucx-post-configure.sh
git diff --check
```

Проверяйте код возврата каждой команды; успешная последняя команда не отменяет ранний сбой. На Linux `PYTHONPATH=src:tests`. Linux/systemd-проверки, пропущенные на Windows, отмечайте как пропущенные, а не как пройденные.

Результаты текущей подготовки публикуются в [описании поставки](RELEASE_RU.md). Исторические числа старой ветки не являются результатами этой копии.
