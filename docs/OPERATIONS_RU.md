# Эксплуатация x-tuna

## Ежедневный контроль

```bash
sudo x-tuna --audit
sudo x-tuna --validate
sudo lucx-sub-repair --check
systemctl --failed --no-pager
```

`active` у systemd-службы или открытый socket не доказывают, что внешний маршрут
работает. Проверяйте также TLS, HTTP marker заглушки, подписку и VPN handshake.

## Долгие операции

```bash
cat /var/lib/lucx-post-configurator/update-status.json
journalctl -u lucx-post-update-repair.service --no-pager -n 100
```

Не удаляйте pending marker и не запускайте второй `--apply`, пока существует
активный worker или mutation lock.

## Условия завершённого обновления

Обновление считается завершённым только если worker завершился с кодом 0, `x-ui`
и ingress active, listeners присутствуют, `--validate` возвращает `ok=true`,
repair-check исправен, а marker удалён worker’ом.

## Безопасный аварийный порядок

```text
остановить новые изменения
  -> сохранить status и journal
  -> выполнить repair-check
  -> применить repair после просмотра плана
  -> проверить validate и внешние endpoints
  -> rollback только из проверенного backup
```

Нельзя вручную редактировать Naive Caddyfile, базу LucX, firewall или удалять
файлы задания. Пользовательский каталог сайта не перезаписывается без согласия.

## Проверка состояния

```bash
sudo x-tuna --audit
sudo x-tuna --validate
sudo lucx-sub-repair --check
```

Эти команды не должны менять конфигурацию.

## Применение плана

```bash
sudo x-tuna --plan
sudo x-tuna --apply
```

Перед подтверждением проверьте домены, порты, службы, backup и список
разрешённых полей базы. Если есть сомнение, выбирайте цифровой вариант отказа.

## Ремонт после обновления

```bash
sudo lucx-sub-repair --check
sudo lucx-sub-repair --apply
```

Ремонт перечитывает актуальную топологию LucX и восстанавливает управляемую
обвязку. Он не должен молча принимать добавленные или удалённые inbound’ы.

## Откат

```bash
sudo x-tuna --rollback
```

Откат выполняется только к backup, который был создан самим конфигуратором и
прошёл проверку целостности.

## Обновление LucX

Автоматический запуск через TUI/`--update-lucx` временно заблокирован:
проверенного адаптера официального updater без автоматического reboot ещё нет.
Отказ происходит до подготовки обновления, `--yes` не обходит запрет. Старые
worker-задания тоже не выполняются; их сохранённый `queued` не означает запуск.
Описанная ниже очередь сохранена для будущего безопасного адаптера.

После появления проверенного безопасного адаптера worker должен продолжать
работу после остановки панели. До этого автоматический запуск недоступен.
Pending marker не удаляйте вручную; после отдельно разрешённого обновления
проверьте `lucx-sub-repair --check` и `x-tuna --validate`.
